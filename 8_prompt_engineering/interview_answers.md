# Ответы: Prompt Engineering

**1.** Роль, контекст, цель, ограничения, формат ответа, примеры (few-shot).

**2.** Few-shot даёт примеры желаемого поведения; лучше для форматов/стиля.

**3.** Просьба рассуждать по шагам для сложной логики; для кода — план→патч.

**4.** Сохранить поведение, указать тесты, маленький diff, не менять публичный API без нужды.

**5.** Давать релевантные файлы/сигнатуры, не весь репозиторий.

**6.** Стабильные правила ассистента (стиль, стек, запреты).

**7.** Часто лучше уточнять по шагам с проверкой тестами.

**8.** Требовать опираться на присланный код; проверять API по docs/анализатору.
