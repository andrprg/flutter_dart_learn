# Ответы к задачам (Типичные ошибки Junior Flutter разработчиков)

**ЗАДАЧА 1: Ошибка обновления состояния**
Вызов `setState` во время фазы `build`. Это приведет к бесконечному циклу перерисовок или ошибке `setState() or markNeedsBuild() called during build`.

**ЗАДАЧА 2: Ошибка верстки (Unbounded height)**
`ListView.builder` внутри `Column` без ограничения высоты. Нужно обернуть `ListView.builder` в `Expanded` или `Flexible`, либо задать `shrinkWrap: true`.

**ЗАДАЧА 3: Утечка памяти (Controller)**
Забыт метод `dispose` для `TextEditingController`. Контроллеры нужно обязательно очищать при уничтожении виджета.

**ЗАДАЧА 4: Неправильное использование FutureBuilder**
Метод `fetchData()` вызывается прямо в методе `build`. При каждой перерисовке виджета (ребилде) `Future` будет запускаться заново. Нужно вынести вызов в `initState` и сохранить `Future` в переменную состояния.

**ЗАДАЧА 5: BuildContext через асинхронный разрыв**
Использование `context` после `await` без проверки `mounted`. Виджет может быть уже удален из дерева к моменту завершения `Future`.

**ЗАДАЧА 6: Переполнение (Overflow) в Row**
Длинный текст внутри `Row` вызовет ошибку `RenderFlex overflowed`. Текст нужно обернуть в `Expanded` или `Flexible`.

**ЗАДАЧА 7: Асинхронный initState**
Метод `initState` не должен быть `async`. Он должен выполняться синхронно. Асинхронную логику нужно выносить в отдельный метод и вызывать его из `initState`.

**ЗАДАЧА 8: MediaQuery/Provider в initState**
Использование `MediaQuery.of(context)` (или других InheritedWidget) в `initState`. В этот момент `context` еще не полностью привязан к дереву. Лучше использовать `didChangeDependencies`.

**ЗАДАЧА 9: Изменение состояния без setState**
Изменение переменной `isActive` без вызова `setState()`. UI не обновится, так как Flutter не узнает об изменении состояния.

**ЗАДАЧА 10: Проблема производительности (ListView)**
Использование `ListView` с `List.generate` для большого списка. Это создаст все элементы сразу. Для больших списков нужно использовать ленивый `ListView.builder`.

**ЗАДАЧА 11: GestureDetector на пустом Container**
`GestureDetector` на `Container` без цвета. По умолчанию пустой контейнер не обрабатывает нажатия (клики проходят насквозь). Нужно добавить `color: Colors.transparent` или `behavior: HitTestBehavior.opaque`.

**ЗАДАЧА 12: SnackBar в initState**
Вызов `ScaffoldMessenger.of(context)` в `initState`. `Scaffold` еще не построен. Нужно использовать `WidgetsBinding.instance.addPostFrameCallback`.

**ЗАДАЧА 13: Забытый super.initState**
Пропущен обязательный вызов `super.initState()` в начале метода `initState`.

**ЗАДАЧА 14: Expanded внутри Stack**
Виджет `Expanded` можно использовать только внутри `Row`, `Column` или `Flex`. Внутри `Stack` нужно использовать `Positioned` или `Align` (хотя `Align` не расширяет, а позиционирует).

**ЗАДАЧА 15: Ошибка TickerProvider**
Пропущен mixin `SingleTickerProviderStateMixin` у класса `State`, из-за чего `this` не является `TickerProvider` и не может быть передан в `vsync`.

**ЗАДАЧА 16: Утечка памяти (Timer)**
Таймер не отменяется в методе `dispose` (`_timer?.cancel()`), что приведет к утечке памяти и ошибкам, если таймер сработает после удаления виджета.

**ЗАДАЧА 17: Мутабельное поле в StatelessWidget**
Поля в `StatelessWidget` должны быть `final`. Состояние не должно меняться внутри виджета без состояния.

**ЗАДАЧА 18: ListView.builder без itemCount**
Пропущен параметр `itemCount` в `ListView.builder`. Без него список считается бесконечным, что приведет к `RangeError` при попытке доступа к элементу за пределами массива `items`.

**ЗАДАЧА 19: Отсутствие Key при изменении списка**
Stateful виджеты (`_ColorBox`) в динамическом списке без `Key` теряют или путают свое состояние при изменении порядка элементов. Нужно добавить `Key` (например, `ValueKey`).

**ЗАДАЧА 20: Навигация в методе build**
Нельзя вызывать навигацию (`Navigator.push`) напрямую в методе `build`. Это ломает жизненный цикл и вызывает ошибки при отрисовке.

**ЗАДАЧА 21: Вложенные Scaffold**
Использование `Scaffold` внутри другого `Scaffold`. Это ломает UI, обработку клавиатуры, плавающие кнопки и снэкбары.

**ЗАДАЧА 22: Бесконечная высота в Column**
Использование `double.infinity` по вертикали (`height`) внутри `Column` вызывает ошибку `BoxConstraints forces an infinite height`. `Column` сам по себе не ограничивает высоту детей. Нужно использовать `Expanded`.

**ЗАДАЧА 23: Positioned вне Stack**
Виджет `Positioned` работает только если его прямой родитель — `Stack`. Иначе возникнет ошибка во время выполнения.

**ЗАДАЧА 24: Тяжелые вычисления в build**
Тяжелые синхронные вычисления (например, огромный цикл) блокируют UI поток (Main Isolate) при каждом ребилде, вызывая зависание (jank) интерфейса. Их нужно выносить в `Isolate` (через `compute`).

**ЗАДАЧА 25: setState после dispose**
Если виджет уничтожен до завершения асинхронной операции (Future), вызов `setState` вызовет ошибку. Нужно проверять `if (mounted)`.

**ЗАДАЧА 26: Theme.of(context) до MaterialApp**
Попытка получить `Theme.of(context)` используя `context` виджета, который находится ВЫШЕ `MaterialApp` в дереве. Нужно использовать `Builder` или вынести `Scaffold` в отдельный виджет.

**ЗАДАЧА 27: Утечка ScrollController**
Забыт метод `dispose` для `ScrollController`. Контроллер скролла нужно очищать, чтобы избежать утечек памяти.

**ЗАДАЧА 28: Неправильный формат цвета**
`0xFFFFFF` означает полностью прозрачный белый цвет (альфа-канал `00`). Правильный формат непрозрачного цвета: `0xFFFFFFFF` (где первые `FF` — это 100% opacity).

**ЗАДАЧА 29: Эффект InkWell перекрыт Container**
Цвет `Container` перекрывает анимацию (splash эффект) от `InkWell`. Чтобы эффект был виден, цвет нужно задавать внутри `Ink(color: ...)` или в `Material(color: ...)`, оборачивая `InkWell`.

**ЗАДАЧА 30: Использование List.generate вместо ListView.builder**
Создание огромного количества виджетов сразу с помощью оператора spread (`...List.generate(5000, ...)`) внутри `Column`. Это приведет к сильным тормозам и крашу из-за нехватки памяти. Нужно использовать ленивую загрузку через `ListView.builder`.
