# Ответы: Null Safety

**1.** В Dart типы по умолчанию non-nullable. `T?` — nullable. Нет `undefined`. Операторы `?.`, `??`, `??=`, `!`. Flow analysis промоутит тип после проверки на null.

**2.** Только когда вы доказали себе, что значение не null (или после проверки, которую анализатор не видит). Иначе — runtime crash. На собеседовании лучше говорить: предпочитаю `??` / early return / promotion.

**3.** `late` откладывает инициализацию. `late final` — один раз. Если прочитать до записи — runtime error. Нужен, когда поле нельзя сделать nullable, но инициализация не в конструкторе.

**4.** Локальные переменные промоутятся после `if (x != null)`. Поля класса — нет (могут измениться Concurrently), поэтому копируют в локальную `final v = field;`.

**5.** `?.` — безопасный вызов метода/доступа. `??` — выбор значения, если левый операнд null.

**6.** Для `null` — `null`. Для пустого — throw `StateError` (first на пустом списке).

**7.** Делает named-параметр обязательным при null safety; без default нельзя вызвать, не передав значение.

**8.** `map[key]` всегда `V?`. Нельзя считать non-null без проверки. Используйте `containsKey`, `??`, pattern matching.
